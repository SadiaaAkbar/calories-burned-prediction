# 🔥 Calories Burned Predictor

An end-to-end machine learning project that predicts calories burned in a gym
session from a person's body stats, heart rate, and workout details — deployed
as a live, interactive Streamlit app.

**[▶ Live App](#running-the-app)** · **[📊 Model Comparison](#results)** · **[📝 Case Study](CASE_STUDY.md)**

---

## Problem Statement

Gym-goers and fitness apps constantly estimate "calories burned" per session,
but most consumer wearables use fairly crude formulas (heart rate + duration
only). This project asks: **can we build a more accurate calorie-burn
estimate using a fuller picture of the session** — body composition, workout
type, heart-rate dynamics, and training experience — and can we do it with a
model simple enough to run instantly in a lightweight app?

The target audience is fitness apps, personal trainers, and gym-goers who
want a quick, personalized calorie estimate without a wearable device.

## Dataset

978 gym session records with the following raw features: age, gender,
weight, height, max/average/resting heart rate, session duration, workout
type (Cardio / Strength / HIIT / Yoga), body fat %, water intake, workout
frequency, experience level, and BMI. Target: `Calories_Burned`.

> **Data note:** This repo ships with `data/gym_data.csv`, a dataset
> generated by `data/generate_data.py` to match the exact schema,
> distributions, and correlations of the public
> [Gym Members Exercise Dataset](https://www.kaggle.com/datasets/valakhorasani/gym-members-exercise-dataset)
> (Kaggle, 973 rows). To use the original Kaggle data 1:1, download it and
> overwrite `data/gym_data.csv` with the same column names — no other code
> changes needed.

## Approach

1. **Data cleaning** — dropped duplicate rows, imputed missing `Fat_Percentage`
   values using the gender-group median, filtered out physiologically
   impossible rows (e.g. invalid BMI/age ranges).
2. **EDA** — explored the calorie distribution, relationships between session
   duration/heart rate and calories burned, differences across workout types,
   and a full correlation matrix (see `figures/eda_overview.png`).
3. **Feature engineering**
   - `HR_Reserve` = Max BPM − Resting BPM (aerobic capacity proxy)
   - `HR_Intensity` = (Avg BPM − Resting BPM) / HR Reserve (% of heart-rate reserve used)
   - `Weight_x_Duration` = interaction term capturing total mechanical work
4. **Model training & comparison** — trained and cross-validated 6 regression
   models: Linear, Ridge, Lasso, Random Forest, Gradient Boosting, and SVR.
5. **Evaluation** — compared models on 5-fold CV R² and held-out test R² /
   MAE / RMSE; selected the best performer automatically.
6. **Deployment** — wrapped the winning model in a Streamlit app where users
   enter their own stats and get an instant prediction plus a comparison to
   peers doing the same workout type.

## Results

| Model | CV R² | Test R² | Test MAE (kcal) | Test RMSE (kcal) |
|---|---|---|---|---|
| **Gradient Boosting** ⭐ | 0.940 | **0.955** | **60.5** | 73.6 |
| Random Forest | 0.921 | 0.930 | 69.2 | 91.0 |
| Lasso Regression | 0.916 | 0.913 | 76.3 | 101.9 |
| Linear Regression | 0.916 | 0.912 | 76.3 | 102.3 |
| Ridge Regression | 0.916 | 0.912 | 76.4 | 102.3 |
| SVR (RBF) | 0.893 | 0.897 | 78.6 | 110.7 |

**Gradient Boosting** was selected as the final model — it explains ~95% of
the variance in calories burned with an average error of ~60 kcal per
session. Full comparison in `models/model_comparison.csv`.

Session duration and average heart rate were the strongest predictors of
calories burned (see `figures/feature_importance.png`), consistent with
exercise-physiology fundamentals.

## Running the Project

### 1. Setup
```bash
git clone <this-repo-url>
cd calories-burned-predictor
pip install -r requirements.txt
```

### 2. Reproduce the training pipeline
```bash
python data/generate_data.py   # or replace data/gym_data.csv with the real Kaggle file
python train.py
```
This cleans the data, runs EDA (figures saved to `figures/`), engineers
features, trains all 6 models, and saves the best one to `models/`.

Alternatively, open `Calories_Burned_Predictor.ipynb` in Jupyter to walk
through the same pipeline interactively, with EDA plots and results inline:
```bash
jupyter notebook Calories_Burned_Predictor.ipynb
```

### 3. Run the app
```bash
streamlit run app.py
```
Then open the local URL Streamlit prints (usually `http://localhost:8501`).
